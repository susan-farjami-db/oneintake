# Assumptions and decisions log

Each entry: the decision, then the reason.

## Repo and scaffold
- **A1. Built on the existing `OneIntake` APX scaffold** (created by `apx init`, single `init` commit). The older `project-intake` folder was not reused because it carries a real company name.
- **A2. File-count rule (30 files max) counts authored files only.** Files created unchanged by `apx init` (core backend helpers, shadcn `components/ui`, lockfiles, agent config folders), generated data (`data/raw`), and `evidence/` outputs are excluded. The scaffold alone ships more than 50 files, so a literal count could not be met while also running `apx init`.
- **A3. Removed example pages**: `/profile`, the landing page, and the bubble background. `/` redirects to `/submit`.

## Data
- **A4. Config lives in `config/`** (`form_fields.json`, `app_config.json`). It is packaged into the app wheel so the deployed backend reads the same files.
- **A5. No Faker at runtime.** The generator uses only `data_gen/names.py` lists. Faker is a dev dependency used only by the test that proves no Faker company names appear.
- **A6. 18 planted near-duplicate pairs.** 10 existing sides are projects in `project_tracker.json` and 8 are earlier requests. Every new side is a recent `submitted` request in the CSV, including "Chatbot so agents can check load ETA".
- **A7. Ambiguous requests have one primary label and 1 to 2 secondary labels.** 5 of them are in `eval/labeled_categories.csv` with the primary label as the truth.
- **A8. Duplicate eval set = 18 positives + 22 negatives.** Negatives include hard cases: the same subject in a different category, and the same category with a different subject.
- **A9. `data/raw/` is gitignored.** It is reproducible from the fixed seed (`20261026`) and is regenerated by the data generation job. The `eval/` label files are committed.

## Workspace and platform
- **A10. Databricks profile `DEFAULT`** (user choice). The scaffold profile had an expired refresh token.
- **A11. Existing catalog `oneintake_demo` instead of `oneintake_catalog`** (user choice). `CREATE CATALOG` was denied on the shared metastore. The catalog stays the bundle variable `catalog`, so another target can point at a dedicated catalog.
- **A12. Lakebase Autoscaling (`postgres_projects`) instead of provisioned instances.** Provisioned Lakebase is retired for new work, and apps bind Autoscaling databases through the `postgres` resource key. Auth uses `w.postgres.generate_database_credential` (1-hour OAuth token); there are no static passwords.
- **A13. Lakebase-to-bronze uses Lakehouse Sync (CDF config `app_to_raw`, Beta)** into `raw.lb_*_history`. Bronze keeps the latest non-delete change per key. It is reproducible with `ops/run.py cdf`. The first pipeline run quarantined every row because Lakehouse Sync had not yet delivered `form_config`. Run `cdf` and wait for `CDF_STATE_STREAMING` before the first pipeline run.
- **A14. Lakebase IDs are `text`, not `uuid`.** Lakehouse Sync does not support uuid, vector, or array columns. Embeddings therefore live in a separate `serving` schema that is not synced.
- **A15. `projects_synced` fallback.** Synced tables need a Lakebase UC catalog (`CREATE CATALOG`, denied), and the bundle resource is deprecated. `ops/run.py sync-projects` copies `gold.projects` (projects and historical requests, with embeddings) into `serving.projects_synced`. A scheduled job keeps it fresh.
- **A16. pgvector is used; the Vector Search fallback is not needed.** The `vector` extension is available on Lakebase Autoscaling.

## AI functions and duplicate scoring
- **A17. Embedding endpoint `databricks-bge-large-en`** (discovered via the SDK; see `evidence/embedding_endpoint.txt`). It had the best retrieval ranking on the eval pairs among the three available endpoints.
- **A18. Live duplicate score = raw cosine between a BGE query embedding** (query prefix `Represent this sentence for searching relevant passages: `) of the draft text and stored document embeddings. The demo title scores 0.883 against "Agent ETA assistant"; the next match scores 0.708.
- **A19. The "Agent ETA assistant" project description was tightened** so the demo pair passes the 0.85 likely-duplicate band.
- **A20. `ai_classify` and `ai_extract` use `version` `2.1`.** Only 2.1 returns confidence scores. The options map must be a literal, so `classify_instructions` is a pipeline configuration value substituted into the SQL. A test keeps it equal to `config/app_config.json`.
- **A21. Gold duplicate clusters use a separate high-precision `cluster_threshold` (0.92) plus explicit merge links (`duplicate_of`).** Document-to-document cosine on synthetic text separates poorly: at 0.85 it linked 2 of 18 planted pairs and created 18 false links between template-alike rows. At 0.92 there were no false links. `duplicate_rate` therefore reflects Task Force merges, and the 0.85 threshold applies only to the live check, which Phase 6 tunes.
- **A22. The metric view is created by `governance/uc_setup.sql` (section `metric_view`).** Pipelines and bundles have no metric view resource.

## Governance
- **A23. `task_force` is a workspace-local group** created through the workspace SCIM API. No account group existed, and account-level group creation is outside workspace admin rights. The row filter accepts either `is_account_group_member('task_force')` or `is_member('task_force')`, so an account group can replace it later.
- **A24. The pipeline owner must be in `task_force`.** Gold reads the filtered `silver.requests`, so a non-member owner would build gold from one business unit only.
- **A25. Column comments come from one glossary (`ops.column_glossary`) applied by a SQL scripting loop** to every governed table. One comment per column name keeps `uc_setup.sql` under the size limit and covers future columns automatically.
- **A26. Tags follow the existing account tag policies.** `business_unit` is a governed "billed to unit" tag limited to Finance, Legal, Marketing, and Operations. The intake tables are tagged `business_unit = Operations`. `sensitivity` allows pii, internal, and public: email, owner, and sponsor columns and the tables that hold them are `pii`.
- **A27. Row filters, tags, and comments are applied with ALTER after the pipeline runs.** They survived a full pipeline refresh in testing. The setup job reruns the governance section after each pipeline run anyway.
- **A28. The governance self-check flips the runner's own `task_force` membership** to test the non-member path (mapped to Finance), then restores it. It waits for the warehouse membership cache (about 1 minute) and adds a nonce to each query to bypass the result cache.
- **A29. `gold.portfolio_metrics` covers requests only** (`filter: source = 'request'`). It inherits the business-unit row filter from `gold.projects`.

## API
- **A30. The demo pair's new side ("Chatbot so agents can check load ETA") is kept out of the opportunity log.** It is the text the presenter types, so a historical copy would match itself. It stays in `eval/duplicate_pairs.csv` (id `LIVE-DEMO`).
- **A31. The OBO identity is resolved with `current_user.me()` on the user token**, cached for 5 minutes per token hash. It drives `requester_email` (the form field is read-only), `/requests/mine`, the rate-limit key, and the `task_force` check.
- **A32. Calls to the embedding endpoint, `ai_classify`, and Lakebase use the app service principal.** Users then need no warehouse or endpoint grants. The portfolio KPIs are the exception: they run as the user (OBO) so the business-unit row filter applies.
- **A33. The synchronous `ai_classify` omits confidence scores** to keep the category within 5 seconds (about 1 second faster). The pipeline recomputes the category with confidence. Opening the form warms the warehouse in the background.
- **A34. The duplicate search returns the top 3 across `app.intake_requests` (via `serving.request_embeddings`) and `serving.projects_synced`.** Results are deduplicated by key, and rejected items and the caller's draft id are excluded. The backend returns a band for each match, and the UI hides `none`.
- **A35. "Join existing" saves the request as `merged` with `duplicate_of` set**, so the portfolio counts the extra demand without a review step. It skips required-field validation beyond title and description.
- **A36. The scaffold header dependency's `request_id` parameter was renamed to `x_request_id`.** It collided with the `/review/{request_id}` path parameter.
- **A37. The API test runs against live services with the caller's CLI token as the OBO header** and deletes the rows it creates.
